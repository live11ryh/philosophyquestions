哲学知识库 Wiki Schema

这是 Philosophy Wiki 的模式定义文件。它告诉 LLM 如何维护这个知识库。

核心理念

Wiki 是持久性、累积性的知识工件。 当你添加新资料时，LLM 不是简单地索引它供以后检索，而是：

  1. 读取并提取关键信息
  2. 将其整合到现有 wiki 中
  3. 更新相关概念/人物页面
  4. 标注新数据与旧 claims 的矛盾
  5. 加强或挑战正在演变的综合论点

你负责 sourcing、探索和提问。LLM 负责总结、交叉引用、归档和维护。

Ingest 流程（摄入新资料）

当用户要求摄入新资料时：

  1. 读取源资料
  • 阅读原始文件/网页
  • 如有图片，先读文本再单独查看图片获取额外上下文
  1. 讨论关键要点
  • 与用户讨论：这是什么？核心主张是什么？值得强调什么？
  1. 写入摘要页面
  • 在 sources/ 创建新页面

    • -包含基本信息和关键摘录

  1. 更新 index.md
  • 添加新页面的条目
  • 按类别（concepts/entities/sources）组织
  1. 更新相关页面
  • 在相关概念页面添加链接
  • 在相关人物页面添加链接
  • 标注与其他页面的矛盾或补充关系
  1. 记录到 log.md
  • 添加 ingest 条目到日志

Query 流程（回答问题）

当用户提问时：

  1. 读取 index.md 找到相关页面
  2. 阅读相关页面 获取上下文
  3. 综合回答，引用来源
  4. 评估是否值得归档
  • 如果答案是新的分析/比较/洞见，问用户："要保存到 wiki吗？"
  • 如果是，创建新页面并更新 index

Lint 流程（定期审查）

定期检查 wiki 健康状况：

  1. 检查矛盾
  • 页面间的 claims 是否冲突？
  1. 检查陈旧

    2. -是否有被新来源更新的 claims？

  1. 检查孤立
  • 是否有无 inbound 链接的页面？
  1. 检查缺口
  • 重要概念是否缺少独立页面？
  1. 建议新来源
  • 哪些问题需要更多资料来填补？

YAML Frontmatter 字段说明

| 字段 | 必需 | 说明 |
|------|------|------|
| uid | ✓ | 唯一标识符（小写+连字符） |
| title | ✓ | 显示标题 |
| created | ✓ | 创建日期 YYYY-MM-DD |
| updated | ✓ | 最后更新日期 |
| tags | ✓ | 标签数组 |
| type | entities必需 | philosopher/work/movement |
| sources | 推荐 | 相关来源的 uid列表 |
| born/died | 可选 | 哲学家生卒年 |

使用提示

  • Obsidian Web Clipper：安装浏览器扩展，快速将网页转为 markdown
  • 下载图片本地化：设置 → 文件和链接 → 附件文件夹路径
  • Graph View：用 Obsidian 的图谱视图查看 wiki 结构
  • Dataview：用 type:philosopher 等查询生成动态列表
